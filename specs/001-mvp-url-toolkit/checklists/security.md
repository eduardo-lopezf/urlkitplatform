## Protección SSRF: completitud

- [ ] CHK001 ¿Enumera la spec todos los rangos bloqueados (CGNAT, multicast, reservados, no especificados, IPv6 `fc00::/7`, `fe80::/10`, mapeadas IPv4) o solo "privadas, loopback, link-local y metadatos", dejando el resto en research y arquitectura? [Completeness, Spec §FR-032, Gap]
- [ ] CHK002 ¿Están los controles de esquema (`http`/`https`), credenciales en la URL y lista de puertos permitidos (80, 443, 8080, 8443) recogidos como requisitos de la spec, y no solo como decisiones de research R6? [Gap, Spec §FR-032, Research §R6]
- [ ] CHK003 ¿Exige algún requisito que el nombre se resuelva una sola vez, que se validen **todas** las IPs devueltas y que se conecte a la IP validada (fijación de IP), tal como impone la constitución? [Completeness, Constitution §V, Gap]
- [ ] CHK004 ¿Está especificado que el cliente HTTP no sigue redirecciones por su cuenta y que no honra variables de entorno de proxy, o solo se dice en el plan? [Traceability, Constitution §V, Plan §Constitution Check]
- [ ] CHK005 ¿Se define qué ocurre cuando una resolución devuelve una mezcla de direcciones públicas e internas (bloquear todo, no usar solo la primera)? [Edge Case, Spec §FR-032]
- [ ] CHK006 ¿Cubre algún requisito las formas numéricas poco habituales de IPv4 (decimal, hexadecimal, octal, abreviada) como destino a bloquear, no solo como caso a analizar? [Coverage, Spec §Edge Cases, Spec §FR-032]
- [ ] CHK007 ¿Está definido el conjunto de vectores compartidos como artefacto obligatorio (`tests/ssrf-vectors/`) y la condición de que todo servicio que haga peticiones salientes lo supere? [Traceability, Constitution §V, Research §R19]

## Protección SSRF: claridad y límites

- [ ] CHK008 ¿Están cuantificados en la spec el tiempo de espera por salto, el tiempo total de la cadena y el tamaño máximo de cuerpo leído, o FR-033 los deja sin cifra (están en research: 5 s, 15 s, 256 KB)? [Clarity, Spec §FR-033, Research §R6]
- [ ] CHK009 ¿Precisa el límite de tamaño si se mide sobre los bytes recibidos o sobre el contenido descomprimido, para cubrir respuestas comprimidas desproporcionadas? [Ambiguity, Spec §FR-033, Gap]
- [ ] CHK010 ¿Se especifica que solo se lee cuerpo en respuestas HTML, y qué se considera HTML (tipo de contenido declarado o detectado)? [Clarity, Research §R6]
- [ ] CHK011 ¿Está definido qué hace el inspector ante un error de certificado TLS (detenerse con su código, nunca continuar sin verificar) como requisito y no solo como caso límite? [Clarity, Spec §Edge Cases, Gap]
- [ ] CHK012 ¿Es "segunda barrera de egress" un requisito verificable del despliegue (qué rangos, en qué entorno, qué se hace si el proveedor no permite filtrar), o solo una declaración de principio? [Measurability, Constitution §V, Arquitectura §13]

## Seguimiento de enlaces en páginas (FR-037, JavaScript, meta refresh)

- [ ] CHK013 ¿Es coherente el caso límite "las redirecciones JavaScript se detectan y se informan pero no se ejecutan" con el modelo de datos, que las **sigue** si son una asignación literal a `location`? ¿Queda claro que seguir no es ejecutar? [Conflict, Spec §Edge Cases, Data Model §RedirectChain]
- [ ] CHK014 ¿Está definido con precisión "idéntico" en FR-037 (normalización previa o no, mayúsculas del host, barra final, una sola decodificación del parámetro)? [Clarity, Spec §FR-037]
- [ ] CHK015 ¿Se especifica qué ocurre si la página nombra varias URLs en parámetros, o si varios enlaces coinciden con ellas? [Edge Case, Spec §FR-037]
- [ ] CHK016 ¿Se analiza en los requisitos si FR-037 permite a una página dirigir el inspector a un destino elegido por el atacante, y se deja explícito que ese salto pasa la validación SSRF completa? [Coverage, Spec §FR-037, Spec §FR-032]
- [ ] CHK017 ¿Está definido qué se considera "literal" en una redirección JavaScript (comillas, plantillas, concatenaciones), para que la regla de seguimiento sea verificable? [Measurability, Data Model §RedirectChain, Gap]

## Datos de usuario: registros, trazas, métricas y terceros

- [ ] CHK018 ¿Define FR-005 qué significa "en claro": ¿se permite guardar o registrar una URL en forma derivada (hash, dominio registrable), y en qué casos? [Ambiguity, Spec §FR-005]
- [ ] CHK019 ¿Es coherente FR-005 ("las URLs no se registran") con la arquitectura, que permite el dominio registrable en las trazas? ¿Queda escrito que el dominio registrable es la única parte de la URL admitida en trazas y en qué señales no lo está (registros, métricas)? [Conflict, Spec §FR-005, Arquitectura §12]
- [ ] CHK020 ¿Prohíbe algún requisito explícitamente que la IP aparezca en registros, trazas y servicio de errores, o la prohibición solo está en la constitución y en privacidad.md? [Traceability, Constitution §V, Gap]
- [ ] CHK021 ¿Se considera el servicio de errores (Sentry) un tercero a efectos de FR-005, y están definidas las condiciones (depuración verificada, campos permitidos) para enviarle datos? [Ambiguity, Spec §FR-005, Research §R8]
- [ ] CHK022 ¿Son coherentes los resultados medibles en privacidad.md ("éxito o error") con los del contrato (`success`, `error`, `copied`, `sent-to`)? [Conflict, Privacidad §Qué se mide, Contracts §openapi.yaml]
- [ ] CHK023 ¿Es coherente privacidad.md (evento enviado con `sendBeacon`) con la decisión registrada en research R8 (`fetch` con `keepalive`)? Un documento público de garantías no debe describir un mecanismo distinto del real. [Conflict, Privacidad §Qué se mide, Research §R8]
- [ ] CHK024 ¿Se exige que el inspector no reenvíe al destino ningún dato del visitante (IP, cabeceras, `Referer`, cookies), que es la garantía que promete privacidad.md? [Gap, Privacidad §Qué gana Redirect Inspector]
- [ ] CHK025 ¿Están definidos los requisitos sobre los registros del CDN y del proveedor de la API (que no incluyan rutas ni consultas) como criterio de elección verificable, o solo como intención? [Assumption, Privacidad §Lo que no podemos evitar]

## Seudonimización y cuotas

- [ ] CHK026 ¿Recoge la spec la reducción de IPv6 al prefijo `/64` y el algoritmo (HMAC-SHA256 con clave diaria derivada de un secreto), o FR-036 solo dice "hash con una clave que rota a diario"? [Completeness, Spec §FR-036, Research §R7]
- [ ] CHK027 ¿Está definido el huso horario y el instante de rotación de la clave diaria, y su relación con la ventana diaria del contador? [Clarity, Spec §FR-036]
- [ ] CHK028 ¿Hay requisitos para el secreto del servidor (longitud mínima, dónde se guarda, qué pasa si falta o se filtra, cómo se rota)? [Gap, Spec §FR-036]
- [ ] CHK029 ¿Define algún requisito de quién se fía para obtener la IP del cliente detrás de un proxy (`X-Forwarded-For`) y qué ocurre si la cabecera llega de un origen no fiable? Sin esto, la cuota se elude falsificando la cabecera. [Gap, Spec §FR-034, Security §En alcance 4]
- [ ] CHK030 ¿Está especificado el comportamiento cuando el almacén de contadores no está disponible: rechazar (cerrado) o permitir sin contar (abierto), y si difiere entre Redirect Inspector y el resto de endpoints? [Gap, Exception Flow, Spec §FR-034]
- [ ] CHK031 ¿Está definido si las peticiones inválidas consumen cuota, y si una petición rechazada por cuota cuenta en otras ventanas (hora y día)? [Clarity, Spec §FR-034, Arquitectura §4]
- [ ] CHK032 ¿Está documentada la protección del contador de métricas contra eventos falsos que inflen los contadores (límite de 300/hora como única defensa aceptada, o algo más)? [Assumption, Spec §Assumptions]

## Presentación segura (XSS y esquemas peligrosos)

- [ ] CHK033 ¿Exige la spec el escape de todas las salidas, o solo que los esquemas peligrosos no sean enlaces activos? El escape está en la constitución pero no en un FR. [Gap, Constitution §V, Spec §Edge Cases]
- [ ] CHK034 ¿Se especifica cómo se presentan las URLs de los saltos y del destino final del inspector (texto inerte o enlace activo, y con qué atributos si es enlace)? [Coverage, Spec §FR-030]
- [ ] CHK035 ¿Se exige que el desenvolvimiento de Smart Cleaner solo produzca destinos `http`/`https`, para que limpiar nunca convierta un enlace en `javascript:` o `data:`? [Gap, Spec §FR-011, Security §En alcance 5]
- [ ] CHK036 ¿Es verificable el requisito de que la "limpieza máxima" no cambie el contenido al que lleva el enlace (FR-012): con qué criterio se juzga que dos URLs llevan al mismo contenido? [Measurability, Spec §FR-012, Spec §SC-002]
- [ ] CHK037 ¿Están las cabeceras de seguridad de la web (CSP estricta sin scripts en línea de terceros, `Referrer-Policy`, `Permissions-Policy`, HSTS) definidas como requisito con su política concreta, o solo como tarea? [Gap, Tasks §T099]

## Enlaces compartibles y almacenamiento en el navegador

- [ ] CHK038 ¿Define la spec el texto o el momento del aviso antes de copiar un enlace compartible (siempre visible, al pulsar, confirmación) de forma verificable? [Clarity, Spec §Assumptions, Spec §FR-003]
- [ ] CHK039 ¿Se tratan en los requisitos las URLs con credenciales o tokens dentro de un enlace compartible, y el hecho de que el fragmento queda en el historial del navegador? [Coverage, Spec §FR-005, Gap]
- [ ] CHK040 ¿Está acotado por requisito que lo único guardado en el navegador es la preferencia de modo, y que ninguna URL se escribe en `localStorage` ni en el fragmento sin acción explícita? [Completeness, Spec §FR-012, Privacidad §Cookies e identificadores]

## Criterios de aceptación
